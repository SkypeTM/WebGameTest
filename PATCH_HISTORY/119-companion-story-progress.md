# 119 — 동료 개인 이야기 읽음 기록

## 목적
동료 이야기를 끝까지 읽고 명시적으로 완료한 기록을 계정에 저장한다. 이야기를 열거나 중간에 닫는 것만으로는 완료하지 않는다.

## 저장 및 행동 계약
- 기존 `POST /api/game`의 행동에 `{ "type": "completeCompanionStory", "id": "AR1-1" }`을 전달한다. 기존 인증·조작권·저장 버전·요청 ID 규칙을 그대로 따른다.
- UI는 마지막 대사에서 사용자가 완료 버튼을 누를 때만 행동을 전송한다. 성공 응답 전에는 완료 표시를 확정하지 않는다.
- `Game.completedCompanionStories?: string[]`에 완료한 이야기 ID를 저장한다. 기존 저장 데이터는 빈 목록으로 읽으며, 정규화 시 알 수 없는 ID와 중복을 제거한다.
- 서버는 프롤로그 완료·거점 상태·실제 이야기 ID·동료 보유·완료 퀘스트·팩션 우호도를 재검사한다. 잠긴 이야기나 영입하지 않은 동료를 완료 처리할 수 없다.
- `companionStories(game, hero)`는 기존 반환값에 `completed: boolean`을 추가한다. 잠긴 이야기는 계속 `lines: []`이며, 읽음 이력은 해금 조건을 대신하지 않는다.
- 완료 이력은 환생 후에도 유지한다. 퀘스트·우호도가 초기화되면 해금 조건을 다시 충족해야 본문을 읽을 수 있다.
- 같은 이야기를 반복 완료해도 ID가 중복되지 않는다. 동일 요청 ID 재전송은 기존 저장 계층의 결과 재사용을 따른다. 새로운 요청은 기존 계약에 따라 저장 버전만 갱신할 수 있다.
- 재화·우호도·업적·전투·로그 보상은 추가하지 않는다. 읽음 기록을 위한 별도 DB 테이블이나 마이그레이션은 필요하지 않다.

## 변경 파일
- `lib/game.ts`: 저장 필드, 기본값, 저장 호환, 완료 행동.
- `lib/companion-story-progress.ts`: 서버와 화면이 공유하는 해금 판정 및 유효한 완료 ID 정규화.
- `lib/companion-stories.ts`: 읽음 여부 제공 및 보유 동료 조건 일치.
- `CompanionStoryDialog`, `TavernDossier`, `app/page.tsx`: 마지막 대사의 완료 버튼, 읽음/다시 읽기 표시, 저장 중 입력 방지와 실패 안내를 연결한다. 서버 응답에 완료 ID가 있는 경우에만 읽음으로 표시한다.
- `CompanionStoryDialog.module.css`: 완료 버튼·저장 안내 스타일.

## 확인 범위
사용자 지시에 따라 테스트·브라우저·플레이 QA를 실행하지 않았다. 서버 계약 구현과 화면 검증·배포 완료 여부는 구분한다. 이 기록 자체는 배포 완료를 뜻하지 않는다.
