# 035 · SD 횡배열 전투와 몬스터 원본 복구

## 목적과 원인
전열 1번은 오른쪽, 후열 4번은 왼쪽에 배치한다. 기존 몬스터 파일은 부정확한 시트 분할로 신체가 잘리고 다른 개체를 포함했다. 대상 연결선도 실제 좌표가 아닌 고정 좌표를 사용했다.

## 구현
- 캐릭터 32명의 개별 SD 원본 및 변경 요새 M01–M08 개별 몬스터 원본 생성.
- 투명 PNG 원본은 `art-source/sd`, 게임용 WebP는 `public/assets/sd`에 보존. 원본 해상도 유지, WebP quality 94 / alpha 100, 40개 총 15.38 MiB.
- 실제 파티 순서와 저장 데이터는 유지하고 화면만 오른쪽부터 전열 1→4 순으로 배치.
- SD 전신 contain 표시, 공격·피격·방어·회복·사망 모션 및 컷인에 적용.
- 실제 액터 위치를 측정하는 연결선과 대상 강조. 화면 크기 및 이미지 로딩 후 재측정.
- 카드 버튼을 누르지 않은 마우스 이동이 드래그로 인식되던 오류 수정.
- 종료된 전투 효과가 연결선을 숨기거나 컷인을 계속 유지하던 조건 수정.
- 몬스터·Live2D 매니페스트와 기존 분할/FHD 스크립트가 복구된 개별 자산을 유지하도록 수정.
- PATCH_HISTORY 색인에 누락된 034 및 이번 035 추가.

## 주요 변경 파일
`app/page.tsx`, `app/battle-stage.css`, `app/components/BattleTargetLines.tsx`, `data/sd_asset_manifest.json`, `data/monster_asset_manifest.json`, `data/live2d_manifest.json`, `scripts/build-sd-assets.mjs`, `scripts/slice-monster-assets.py`, `scripts/build-fhd-assets.py`.

## 검증
- TypeScript 통과, 게임/저장 테스트 27/27 통과, Cloudflare 프로덕션 빌드 통과.
- 이전 작업 구간의 Codex 내부 로컬 전투: AR1→AR4 오른쪽부터 동일 높이 배치, 공격 후 M01 HP 30→6, 다음 카드 연결선 복원, 단순 호버 시 드래그 유령 없음.
- 원본/QA 시트 시각 검수 및 변환 시 40개 알파 채널 확인. 로컬 AR1/M08 WebP HTTP 200.
- Cloudflare 배포: 2026-09-26, version `06f116f3-1732-4c1c-9a34-a79ef826dce6`.
- Codex 내부 라이브 화면: 기본 파티 4명 + M01/M02 로딩 성공, 전신 표시 및 순서 확인, 콘솔 오류 0.
- 라이브 844×390 모바일 가로 / 768×1024 태블릿 세로: 파티 동일 높이 및 오른쪽→왼쪽 순서 유지, 가로 넘침 없음.
- 현재 로컬 오류 페이지 제어는 브라우저 보안 정책으로 차단되어 재검증하지 못함. 라이브 전투 입력은 ‘이 기기에서 이어하기’ 조작권 회수가 자동 승인 검토에서 거절되어 미검증. 읽기 전용 화면 검증만 완료. 사용자 승인 후 카드 사용·저장 확인 필요.

## 범위와 잔여
SD는 개별 정지 일러스트에 런타임 모션/이펙트를 적용한 방식이며 골격 리깅 또는 프레임별 애니메이션이 아니다. 다른 맵 M09–M56은 기존 자산을 유지한다. 원본 생성 프롬프트 규격은 `art-source/sd/README.md`에 기록했다.
